执行者使用可用的仓库、邮箱和文件工具，直接处理真实工作并修改名单。 不绑定执行客户端、模型供应商或操作系统，没有自定义运行脚本、任务注册表或协调系统。

读取 Skill 查看源码

三个成员名单，每库保存工作状态。

待做新库

new-repositories.md：一行一个仓库。处理近期 issue，再审计实际代码；真正完成后移除。

关注旧库

followed-repositories.md：标题下放子列表，允许重合。扫描合并去重，从上次时间接续，不重复全审计。

每库状态与贡献

state.md：巡检、覆盖边界、未完成链接和原因；work.md：实际处理了什么 issue、提交或跟进了什么 PR。中央 unfinished.md 仅为导航视图。

旧库全表

old-repositories.md：完整历史旧库成员名单，不是关注子集；只存仓库名，不重复维护每库状态。

工作区使用相对目录 RepoStew_skills/、state/ 和 work/owner/repo/。记录在仓库容器内，源码在 checkout/；释放源码不删除记录。执行路径以工作区根目录为基准，文档链接以所在文件为基准。

state/read-positions.md 保留仓库通知位置和关注库扫描时间；邮箱位置单独保存在私密的 state/private/mail-position.md。 时间、原生 ID、修订值和边界 ID 精确保留。读到不等于解决。

处理真实工作，不复制交互数据库。

获授权的新库发现直接入池：确认真实身份、应用既定筛选并去重，批量追加新名单末尾。不读简介另判相关性，不提前调查 issue、审计源码或判断能否发 PR。已有库接续原范围，不重置进度、不自动关注；有活跃协调者时安排单写入者，用户指定发现者直接追加则约定短暂写入窗口，协调者期间不改同一名单。不重复搜索或回读验收，不新增锁、队列或调度。

启用 Trending/awesome 来源时，榜单项目、awesome 清单库及清单内 GitHub 项目均为候选；已收录清单仍用于发现。远程提取链接，清单之间有界扩展并防循环，不递归扫描普通项目依赖；来源启用不等于恢复暂停调度。

完整分页获取实际 issue、PR 和讨论，遵守目标仓库规则，调查、修复、验证并完成获授权的提交。 未完成事项先保留链接和原因，再推进读取位置；部分抓取失败保留原位置。

完整未完成巡检枚举每库 state.md，不依赖可能滞后的中央视图。外部贡献库每次工作结束都处理源码释放，包括无改动和阻塞；自有库不适用。依据已确认的交付与占用事实通过门槛后直接删除授权目录，记录操作结果；不盘点独有/未知数据，不新建恢复副本，不做恢复解包/哈希校验、删后复核或磁盘空间检测。仍保护精确授权范围、已知未交付改动和其他任务占用；未过门槛保留，现有归档不动。

通知、邮箱和开放工程巡检保持各自已有边界。默认串行；明确请求并行时，leaf 直接写自己的 state.md/work.md，协调者只写共享名单、导航和跨库位置，完成即补位。不自动创建协调者、子任务或调度层。

可配置轻量周期：每小时通知与选定邮箱文件夹增量，两个平级来源各自保留位置，重复对象合并，不读其他文件夹、不发邮件或改已读。每 6 小时关注库新 issue，按库合并，有事项才派 leaf，复用新库协调者与 leaf，只查相关代码，不重复全审计或改名单。每 24 小时兜底全量找本人创建/评论的开放 issue、创建的开放 PR 和所有每库未完成链接；轻量查状态/head/CI，仅变化、未知处理或仍可推进事项深入处理，不仅依赖 updated_at 判断 CI。

三个巡检入口优先共用现有对话，上一轮未结束就继续，不叠加；跨任务同库不双写。无变化复用结果，不重读、重测或重克隆，不新增交互状态库。仅重要变化、真实交付、失败或需用户操作时通知；周期不保证完成时限，配置不代表巡检证据，规则更新不自动恢复暂停任务。具体周期、来源供应商与执行设置属于工作区配置。

每个 leaf 完成投稿与释放闭环：遵守目标库规定，满足直接投稿门槛优先普通 open PR；草稿需有具体剩余门槛。缺本机原生工具不自动降为草稿，必需格式、邀请或投稿条件不能跳过。核对发布结果、通过释放门槛并删除授权源码后，leaf 直接写每库记录，不要求恢复副本，不再复核删除或磁盘容量。投稿、代码验证、全库完成和删除结果分别记录。

同库复用未变规则与 fork/分支信息，首次完整检查，投稿前查相关增量。测试限受影响范围及目标库强制项；完整 diff、格式和公开文本审阅合为投稿前一次。leaf 确认发布结果，协调者默认信任返回及报告写入，不回读验收。名单计数入口读取一次，导航仅更新受影响库，接收与共享更新及补位一次完成。明确报错、无结果、矛盾或冲突才局部介入，优先原 leaf 修正；不盲重试，不同库双写，连续三次失败保留门槛。一次等待超时不算失败，不加常态心跳或成功抽检；静默错误不能保证被发现。缺陷证明、完整 issue 覆盖和实际代码审计保留，不默认等待 CI 或合并。

缺少 issue/PR 返回时先与原 leaf 交流：已发但漏报就补链接与记录；确实没有则说明原因；原授权内仍能推进就继续。确认后直接接受，不重复搜索、不强造投稿；未答复或写入歧义不算完成，独立库继续。

关注和历史贡献不代表维护权限。私密邮箱、安全材料和凭据不进入公开状态； 未获授权不合并、关闭、发布、删除或推送上游。未知和未提交数据保持原样。

Direct Markdown state. No custom runtime scripts.

Three membership lists: new repositories, the full old-repository inventory and named overlapping followed groups. Per-repository state.md holds patrol facts and unfinished links; work.md records actual issue/PR work. The central unfinished view is navigation only. Three read positions: repository notifications, followed-issue time, and a private mailbox position.

Keep RepoStew_skills/, state/ and work/owner/repo/ relative to the workspace root. Source lives in checkout/, outside persistent records. Document links resolve from their containing file. No execution client, model vendor, operating system or fixed model settings are required.

Use available repository, mailbox and file tools directly. Scan the deduplicated followed union once. Advance only after complete capture and handling or retention; a partial failure preserves the position. Read discussions, reviews and CI live. Historical contributions never imply maintainer authority.
