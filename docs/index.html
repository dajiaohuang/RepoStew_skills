Portable repository stewardship

把贡献做完。
把维护接起来。

一套直接读写 Markdown 的仓库维护 Skill：发现、处理 issue、审计、修复、验证、交付 PR，再持续跟进评审、CI 和未完成事项。不绑定执行器、模型供应商或操作系统，不需要额外运行脚本、数据库或协调服务。

名单选范围。
每库记录存事实。

三个成员名单

新库待处理、旧库历史全表、分组关注名单。名单只保存成员；关注组允许重合，扫描去重并集。

每库两个记录

state.md 保存覆盖、未完成链接与原因、资源结果；work.md 简记实际 issue/PR 贡献。中央 unfinished.md 仅导航。

相对目录，源码可处置

工作区保留 RepoStew_skills/、state/ 和 work/owner/repo/。源码在 checkout/，释放源码不删除记录。

来源独立，隐私隔离

通知与关注扫描位置在 read-positions.md，邮箱位置在 private/。保留原生边界，正文实时读，不复制交互数据库。

一套交付流程。
两种指派范围。

获授权的 Trending、awesome 清单库及清单内项目，确认真实身份、既定筛选并去重后直接追加新库名单末尾，不提前克隆或审计。已有库接续原范围，不重置进度或自动关注。

新库处理完整近期 issue 并审计实际全代码，全部完成才移出新名单。关注旧库只处理本批新 issue 和相关代码，不重复全审计、不改成员名单；没有新 issue 就不开 leaf。

默认串行，明确授权后才并行。轻量协调者抓取、去重、按库分派和补位；leaf 自行调查、修复、验证、投稿、释放，并直接写本库记录。协调者只更新共享名单、导航和位置，信任返回及已报告写入，不重复验收。同库单写入者；发现者直接追加时约定短暂写入窗口。

先读目标政策，证明缺陷，聚焦受影响检查与强制项，合并最终审阅。符合门槛优先普通 open PR，确认实际发布结果；不强造投稿、不默认等 CI 或合并。缺少 issue/PR 结果就问原 leaf，仍可推进则继续；明确失败、矛盾或冲突才局部恢复。

外部贡献源码通过精确授权、交付和非占用门槛后，删除指定 checkout/temp 并记录操作结果。不新建恢复副本，不盘点独有或未知数据，不做删后核验或磁盘检测；保留已知未交付、占用及无关材料、永久记录和现有归档。自有库不适用，不清 Go 缓存或工具链。

及时接续。
低频兜底。

可配置 1／6／24 小时基线：每小时通知与选定邮件文件夹平级增量，各自位置、合并重复对象；每 6 小时完整抓取关注库新 issue，按库分派；每 24 小时全量找本人创建/评论的开放 issue、创建的开放 PR 和全部每库未完成链接。

优先共用现有巡检对话，上轮未结束就继续，不叠加。兜底先看状态、head 与 CI 概况，仅变化、未知处理或仍可推进事项深入处理；不重读整段讨论、重测或重克隆，也不只靠 updated_at 判断 CI 没变化。

只读选定邮件文件夹，不读其他文件夹、不发邮件、不改已读或订阅；实质回复在工程对象完成。完整抓取且处理或可靠保留才推进位置，失败不当空结果。无变化安静，仅进展、失败或需用户决定时通知。

周期与启停由工作区调度配置；Skill 不自动启动任务或恢复暂停计划，周期也不是完成时限。关注和历史贡献不授予维护权限。私密邮件、安全正文、凭据、源码及恢复材料不进入公开状态或备份。

Finish contributions. Continue stewardship.

A portable Skill with direct Markdown state, three membership lists and persistent per-repository records. No extra runtime service, database or required client/vendor.

One lightweight coordinator/leaf delivery flow: new repositories require recent issues and a full code audit; followed batches cover new issues and related code only. Leaves own delivery and records; coordinators trust reported outcomes and react to concrete faults.

Configurable hourly notifications/selected-folder mail, six-hour followed new issues and daily open-object fallback. Independent positions, deduplicated action, unchanged-work reuse and quiet runs. Schedules need explicit authorization; configured is not active or complete.

Authorized external source release keeps records and known undelivered/active material safe, without new recovery copies or post-delete disk checks. Self-owned repositories are excluded. Private sources and credentials stay private.
