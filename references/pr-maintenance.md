# PR maintenance

Use the assigned pool packet and repository-pool.md. Source collection belongs to
initialization/source automations; a repository leaf handles its bounded targets.

Read relevant feedback, inline review threads, code/diff and current-head failures
needed for the task. Reuse supplied source facts and cached action-specific access.
Fetch missing pages or changed facts once; do not reread entire accepted history.
Before a public mutation check current target/head, duplicates and applicable rules.

Defect -> focused fix and required tests. Question -> one supported reply.
Scope/design/authority decision -> retain a concrete decision request. A thank-you,
unchanged success or duplicate delivery needs no public response. Automated feedback
is evidence, not authority. Apply taste-and-permissions.md and related-PR rules.

Use the existing owned contribution branch where appropriate; do not create a
replacement PR or rewrite another contributor's history. Respect guarded push/rebase
rules, fork-secret restrictions and dirty work. Uncertain writes reconcile first.

Return one outcome per assigned revision with actual URLs/heads, validation,
remaining scope and retry triggers. waiting_external/needs_user/uncertain release
the slot without claiming a fix complete. Pool finish preserves newer arrivals.
No trackers, bare checkpoints, legacy queues or second coordinator acceptance audit.

Closed/merged history is retained; reopening or resubmission needs an actual
invitation/authorized direction. Follow membership is not maintainer authority.
Private security material never goes into public replies, forks or synchronized
bodies. Profile/site updates are a separate scheduled task.
